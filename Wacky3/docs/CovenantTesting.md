# Covenant validation and native acceptance

## Automated evidence

`tools/validate_covenant.py` executes the real generated SQL on the pinned BNW + standalone CP151 schema fixture, then runs the production Lua in isolated Lua **5.1** runtimes. `tools/validate_mod.py` also runs pristine and mutated native definitions against the clean fixture and supplementary caches, checks unchanged native rows/all 172 approved companions, parses every Lua file and validates the complete manifest/ZIP/DDS bytes. Source hashes pin the exact v151 commit `44c1e14ff75d80c1dba5c8a71e8289439a53aafb`, including newly reviewed CvCity.cpp and CvUnitCombat.cpp. These are static/simulated checks. They are not an in-game pass or a reconstruction of final native CP balance values.

Lua coverage includes 0/1/3/6/9/12/13 Flames; all Hall thresholds; six-Hall 15/15 totals; capture/transfer/repeated transfer; foreign capture followed by removal; Covenant and minor exclusion; foreign-major destruction after elimination; originally minor cities acquired by majors; Covenant-founder anti-farming across identity rewriting; known script kills; reused coordinates/founding turns/local IDs; multiple pending removals and reload; ScriptData namespace preservation; capital replacement/capture/absence; free-copy cleanup; Hall sale/Gold/Faith purchase/script removal; idempotence; every controller's construction exclusion; native-friendly defense toggle; pre-combat diplomacy repair; lineage upgrade/reload; absent-Covenant early exit; two configured human Covenants; bounded unchanged-state persistence. Test worlds include 4 and 34 majors, human slots 0 and 3, and a Marathon speed binding. Flames have no speed-dependent branch.

Full output is recorded in `tools/Validation.json`. The production source audit asserts pre-removal raze ordering, capture lifetime preservation, ScriptData serialization, native friendly-territory behavior, pre-strength combat callbacks, and attack/defense modifier separation. Art review is retained in `TheCandlekeepersCovenant/Art/Sources/ArtReview.png`.

## Remaining limitations

No perfect engine-wide city-destruction event is claimed. Raw `CvCity::kill` has no verified destruction Lua hook; acquisition also deletes/recreates objects. A missing prior owner entry is insufficient. Scripted founding/ownership/destruction entirely between observable callbacks may be missed or use the last reliably observed owner. Native save serialization, economic collection, actual combat modifiers and graphics/UI still need this checklist. Alternate DLL versions, VP, multiplayer, hotseat and mid-save roster changes are unsupported.
